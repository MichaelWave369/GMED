02 / VERIFICATION POLICY

The GMED standard

A green dot is not a personality trait. We actually check.

01

GERGED

GitHub must report that the pull request was genuinely merged, not merely closed or approved.

02

MREENED

Inspect check runs and legacy commit statuses on the exact merged commit SHA. Pending or failed evidence blocks the stamp.

03

DOCUMENTED

Show individual signals, source links, observation time and a downloadable JSON receipt. Empty evidence means unverified.

THE SERIOUS BIT. GMED reads public GitHub API evidence without authentication. It cannot determine which checks a branch requires, whether code was independently reviewed, or whether a passing test proves correct behavior. Anonymous GitHub API rate limits apply. On errors or incomplete evidence, verification is withheld.

The second verifier re-fetches GitHub evidence through a distinct source implementation, rechecks each outcome and count, and compares its independently reconstructed result against GMED's first receipt. The trust graph must remain acyclic. Both implementations still share GitHub and this repository, so this is not external or cryptographic independence.

The Ouroboros paradox

Try deliberately adding a dependency from GMED back to the auditor that checks it. The software should refuse the loop, rather than proclaiming an infinite chain of approvals.

To perform a real second inspection: use the Verification Desk above, then choose Run Ouroboros / Second Opinion on its completed receipt. This action issues another read-only set of public GitHub API requests.
